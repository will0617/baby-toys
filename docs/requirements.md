# 交通工具图鉴百科 — 需求分析文档

- **项目代号**: baby-toys
- **日期**: 2026-09-29
- **状态**: 已确认（v1.0）
- **文档性质**: 需求分析，不含实现细节（实现见 `docs/execution-plan.md`）

---

## 1. 项目概述

### 1.1 背景

1-3 岁的孩子普遍对交通工具（尤其是小火车）有浓厚兴趣。市面上的幼儿认知 App 普遍存在广告多、强制交互复杂、内容质量参差的问题。本项目为自家孩子打造一个**干净、高质量、零干扰**的交通工具图鉴百科网站。

### 1.2 项目目标

做一个**家长主导操作、孩子看和听**的中英双语交通工具图鉴网站：

1. 孩子能看到真实、清晰、大尺寸的交通工具照片
2. 家长点击即可播放中/英文名称发音，辅助孩子认知学习
3. 支持「自动连播」模式——孩子只需看和听，无需任何操作
4. 手机/平板打开即用，秒开，零成本部署

### 1.3 为什么是网站而不是 App

- 免安装、免审核、免应用商店分发，任何设备打开 URL 即用
- 静态站点可免费托管（Vercel/Netlify/GitHub Pages），零维护成本
- 家长自己就是开发者，迭代方便

## 2. 用户分析

### 2.1 用户角色

| 角色 | 说明 |
|---|---|
| **最终受益者：孩子（1-3 岁）** | 不直接操作设备。需求：大图、清晰声音、节奏舒缓、无干扰弹窗 |
| **操作者：家长** | 单手持机、抱着孩子或把孩子放腿上。需求：单手可达的大按钮、极简导航、无需登录、快速找到孩子想看的车 |

### 2.2 典型使用场景

1. **陪玩认知**：孩子玩玩具时指着某辆车，家长打开图鉴找到同款，点发音给孩子听，建立「玩具 ↔ 真实事物 ↔ 名称」的联结
2. **哄娃神器**：家长忙碌时开启自动连播，孩子自己看和听
3. **睡前/碎片时间**：躺床上一起看几辆车，说说英文名，当轻度英语启蒙

### 2.3 关键体验原则（由用户特征推导）

| 用户特征 | 推导出的设计原则 |
|---|---|
| 1-3 岁注意力短、易被复杂界面干扰 | 界面元素极简，一屏只做一件事 |
| 孩子可能抢设备乱点 | 大按钮、防误触，任何误点都不会进入「回不来」的页面 |
| 家长单手操作 | 核心操作区（发音、下一辆）放在拇指热区 |
| 抱着孩子等待加载 = 灾难 | 静态生成、图片懒加载、预加载下一张 |
| 幼儿听力敏感期 | 发音清晰、语速适中，不用刺耳音效 |

## 3. 功能需求（MVP）

### FR1 分类浏览（首页）

- 首页展示 6 大类入口：**火车、汽车、飞机、船、工程车、应急车**
- 每个入口包含：类别代表性大图标/照片、类别中文名（如「小火车 🚂」）
- 点击进入对应分类页

### FR2 分类页

- 以大图网格展示该类别下所有交通工具（每屏 2-4 个，图占主体）
- 每个卡片：照片 + 中文名 + 英文名
- 点击卡片进入详情页
- 顶部可返回首页；可左右滑动/翻页（条目多时）

### FR3 详情页（核心页面）

- **超大照片**：占据屏幕主体（≥ 60% 视口高度）
- **中文名 + 英文名**：大字号，点击中文名播放中文发音，点击英文名播放英文发音
- **一句话小知识**：中文一句话科普（家长念给孩子听），如「蒸汽火车是世界上最古老的火车，靠烧煤产生蒸汽开动」
- **导航**：「上一辆 / 下一辆」大按钮；返回分类页
- 详情页 URL 可直接定位到某个交通工具（方便分享/收藏给微信家人群）

### FR4 自动连播模式（灵魂功能）

- 详情页提供「自动连播」开关按钮
- 开启后：自动播放当前车发音（中文 → 停顿 → 英文）→ 停留数秒 → 自动切到下一辆 → 循环整个类别
- 每辆车间隔约 5 秒（可后期调优，MVP 取固定值）
- 连播范围内限于当前类别，播完循环
- 任何时候手动点击可退出连播

### FR5 中英双语发音

- 基于 Web Speech API（`speechSynthesis`），零成本
- 中文使用 `zh-CN` 声音，英文使用 `en-US` 声音
- 语速适中偏慢（适合幼儿跟读，`rate` ≈ 0.8-0.9）
- 设备不支持 TTS 或无对应声音时，界面降级提示（发音按钮置灰 + 说明），不影响浏览

## 4. 内容需求

### 4.1 内容范围

6 大类，每类 8-15 种，**总计约 60-90 个条目**（MVP 目标：每类至少 8 种）。

| 类别 | 示例条目（非最终清单） |
|---|---|
| 火车 | 蒸汽火车、高铁（动车）、地铁、有轨电车、货运列车、绿皮火车、单轨列车、登山齿轨火车 |
| 汽车 | 轿车、出租车、公交车、卡车、跑车、SUV、面包车、吉普车 |
| 飞机 | 大客机、直升机、螺旋桨飞机、战斗机、水上飞机、热气球、滑翔机 |
| 船 | 帆船、货轮（集装箱船）、游艇、渡轮、渔船、皮划艇、潜水艇 |
| 工程车 | 挖掘机、推土机、起重机、混凝土搅拌车、压路机、装载机、翻斗车、叉车 |
| 应急车 | 消防车、救护车、警车、清障车、救援直升机、巡逻艇 |

> 注：**不使用托马斯、小猪乔治等版权角色形象**，全部使用真实交通工具照片，版权干净。

### 4.2 数据模型（每个条目）

```ts
interface Vehicle {
  id: string;              // 如 "steam-train"，用于 URL
  nameZh: string;          // 中文名，如 "蒸汽火车"
  nameEn: string;          // 英文名，如 "Steam Train"
  category: CategoryId;    // 所属类别 id
  image: string;           // 图片路径 public/images/...
  factZh: string;          // 一句话小知识（中文，≤40字，家长念给孩子听）
  imageSource: {
    url: string;           // 来源页 URL（版权追溯）
    license: string;       // 许可协议，如 "CC BY-SA 4.0" / "Unsplash License"
    author?: string;       // 作者（按协议要求署名时必填）
  };
}
```

### 4.3 图片资源规范

- **来源**：Wikimedia Commons、Unsplash 等可免费商用的图库
- **质量要求**：主体清晰、构图居中、适合幼儿识别（避免模糊/杂乱/黑暗背景）
- **技术规格**：统一处理为宽约 1200px、WebP 格式（JPEG 兜底）、单张 ≤ 300KB
- **版权合规**：每个条目记录来源 URL 和许可协议，站内提供图片来源与致谢页

### 4.4 发音规范

- 发音文本即 `nameZh` / `nameEn`，无需额外录音文件
- 中文名按普通话发音；英文名使用 TTS 时注意连字符/多词名称的可读性

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| **性能** | 纯静态生成；Lighthouse 移动端 Performance ≥ 90；首屏图片外全部懒加载；连播时预加载下一张图片 |
| **响应式** | 手机/平板**竖屏优先**设计（家长主要持机方式）；桌面端居中最大宽度展示 |
| **可用性** | 所有可点击区域 ≥ 48px；3 次点击内可达任意交通工具详情页；无死胡同页面 |
| **浏览器兼容** | 现代移动浏览器（iOS Safari ≥ 15、Android Chrome ≥ 90）；TTS 不可用时优雅降级 |
| **成本** | 全链路零成本：免费图库 + Web Speech API + 免费托管 |
| **安全** | 无用户输入、无账号、无后端，纯静态，攻击面趋近于零 |
| **可维护性** | 内容（数据）与代码分离，加一个交通工具 = 加一条数据 + 一张图 |

## 6. 范围外（MVP 明确不做）

以下功能已讨论并明确排除在 MVP 之外，避免范围蔓延：

- ❌ 拍照识别玩具（AI 解析）
- ❌ 问答小游戏（听声猜车、看图选名）
- ❌ 收藏 / 最近看过
- ❌ 真实车辆音效（喇叭声、汽笛声）
- ❌ 账号系统、云端同步
- ❌ 后端服务、数据库

以上均为后续版本的候选扩展（见 §9）。

## 7. 技术选型（已确认）

| 项 | 决定 | 理由 |
|---|---|---|
| 框架 | **Astro（静态站点生成）** | 内容驱动型网站的最佳匹配；默认零 JS、构建时生成静态页，性能最优；少量交互用 Islands 按需水合 |
| 交互 | 原生 Web API（`speechSynthesis`）+ 少量 Vanilla TS | 功能简单，无需引入 React/Vue 运行时 |
| 部署 | Vercel 或 Netlify 或 GitHub Pages（静态托管，免费） | 零成本、自动 CI/CD |
| 数据 | Content Collections（TypeScript 类型安全）或 JSON + 校验 | 内容与代码分离，类型保护 |

> 备选方案（Next.js 静态导出、纯 Vanilla）已在方案讨论中评估并排除，过程存档见本文档附录 A。

## 8. 验收标准

MVP 完成的判定条件（全部满足即验收通过）：

1. ✅ 首页可见 6 大类入口，点击进入分类页
2. ✅ 每个分类页 ≥ 8 个条目，全部有照片、中英文名
3. ✅ 任意详情页：大图正常显示；点击中文名播出中文发音；点击英文名播出英文发音（在支持 TTS 的设备上实测通过）
4. ✅ 一句话小知识完整展示，无占位文案
5. ✅ 自动连播：开启后按「中文→英文→停顿→下一辆」循环播放当前类别，手动点击可退出
6. ✅ 手机竖屏（375px 宽）下无横向滚动、无布局破碎，按钮均可单手点击
7. ✅ iOS Safari 实测发音正常（iOS 需首次用户交互后才允许 `speechSynthesis`，连播模式入口设计已兼容此限制）
8. ✅ 图片全部来自免费商用来源，`attribution` 页列出每张图的来源与许可
9. ✅ Lighthouse 移动端 Performance ≥ 90
10. ✅ 数据校验：所有条目字段完整（无空值、无缺图），校验脚本通过

## 9. 后续版本展望（不承诺）

按优先级排序的候选扩展，MVP 验收后视使用情况决定：

1. **真实音效**：车辆喇叭声/汽笛声（寻找免费音效库或自行录制）
2. **问答小游戏**：听发音选图（3 岁后适用）
3. **收藏/最近看过**：localStorage 即可实现，无后端
4. **拍照识别**：接入多模态 AI 识别玩具照片（技术储备：Next.js 迁移或 Astro + Serverless API）
5. **更多类别**：动物、颜色形状等幼儿认知主题
